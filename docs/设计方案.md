## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                     GUI 线程 (PySide6)                       │
│  MainWindow / 侧边栏 / 5 个页面 / 任务卡片 / Toast / 托盘      │
│  QtWebEngine 嗅探页 ──拦截 URL──┐                             │
└───────────────┬─────────────────┼────────────────────────────┘
                │ 命令(排队)        │ 事件(Qt Signal, Queued)
                ▼                 │
┌──────────────────────────────────────┐
│            引擎线程 (asyncio)          │
│  Scheduler ─ Task ─ HTTP层 ─ 限速/重试 │
│      │                                 │
│      ├─ HLS 源   ├─ DASH 源  ├─ FLV 源 │
│      └─ 分片并发下载 → 临时目录 → 合并  │
└───────────────┬──────────────────────┘
                ▼
        ffmpeg 子进程 (probe / concat / mux)
                ▼
        SQLite 任务库 + 任务目录 manifest
```

**关键决策**：GUI 线程与 asyncio 引擎彻底分离。引擎跑在独立线程自己的事件循环里，GUI 通过 `loop.call_soon_threadsafe()` 投递命令，引擎通过 Qt Signal（跨线程自动排队）回推事件。这样网络抖动不会卡界面，也不需要 qasync 那种把事件循环揉进 Qt 的方案。

**线程职责边界**：

| 线程 | 职责 | 禁止 |
|---|---|---|
| GUI 线程 | 渲染、交互、QtWebEngine、文件对话框 | 网络请求、大文件 IO、阻塞等待 |
| 引擎线程 | HTTP、解析、分片下载、调用 ffmpeg、写 SQLite | 触碰任何 QWidget |
| ffmpeg 子进程 | 探测 / 拼接 / 封装 | 由引擎线程通过 asyncio.subprocess 管理 |

### 3.2 QSS 落地的现实约束

Qt QSS 不支持 CSS 变量、`box-shadow`、`transition`、复杂伪类。对应策略：

| 需求 | 实现方式 |
|---|---|
| 主题变量 | Python 渲染模板：`tokens` 注入 `base.qss` 的 `{{bg}}` 占位符，切主题即 `setStyleSheet()` 重建 |
| 卡片阴影 | `QGraphicsDropShadowEffect`（Qt 只支持单层，卡片用 `blur=24, offset=0,2, color=rgba(0,0,0,18)`） |
| 圆角窗口 | `FramelessWindowHint + WA_TranslucentBackground`，外层 8px 透明 padding 容纳阴影，内部 QFrame 画圆角 |
| 进度条 | 自绘 `QWidget.paintEvent`（圆角轨道 + 圆角填充 + 流光渐变更可控，`QProgressBar::chunk` 画不出两端圆角） |
| 悬停过渡 | `QPropertyAnimation` 驱动自定义 `color` property，或直接接受瞬时切换（140ms 以内差别很小） |
| SVG 换色 | 读取 SVG 文本，把 `currentColor` 替换成令牌色后用 `QSvgRenderer` 渲染成 QPixmap |
| 深浅切换 | `app.styleHints().colorScheme()` 跟随系统，或设置页强制 |
| 窗口缩放 | `nativeEvent` 处理 `WM_NCHITTEST` 返回边缘热区码（8px），可得到系统级拖动缩放 |

## 4. 内核设计

### 4.1 状态机

```
QUEUED → PROBING → DOWNLOADING → POSTPROCESSING → COMPLETED
   │         │          │              │
   └─────────┴──────────┴──────────────┴──→ PAUSED / FAILED / CANCELED
```

- 只有 `PAUSED` / `FAILED` 可恢复；`COMPLETED` / `CANCELED` 为终态
- 应用启动时把所有 `DOWNLOADING` / `POSTPROCESSING` 重置为 `PAUSED`，并提示"3 个任务可恢复"
- 任务并发默认 2（设置可调 1–5），每任务分片并发默认 16（1–32）

### 4.2 核心数据模型（`core/models.py`）

```python
class TaskStatus(str, Enum):
    QUEUED = "queued"
    PROBING = "probing"
    DOWNLOADING = "downloading"
    POSTPROCESSING = "postprocessing"
    COMPLETED = "completed"
    PAUSED = "paused"
    FAILED = "failed"
    CANCELED = "canceled"


class Task:
    id: str                          # uuid4
    url: str
    protocol: Literal["hls", "dash", "flv", "direct"]
    title: str
    status: TaskStatus
    # 进度
    bytes_done: int
    bytes_total: int
    segments_done: int
    segments_total: int
    speed_bps: float
    eta_seconds: int | None
    # 配置快照（创建时冻结，便于重试复现）
    headers: dict[str, str]
    options: DownloadOptions         # variant / container / concurrency / rate_limit
    output_dir: str
    output_path: str | None
    error: str | None
    created_at: datetime
    updated_at: datetime
```

### 4.3 引擎线程与事件

```python
class EngineThread(QThread):
    """持有独立 asyncio 事件循环，所有下载逻辑都在这里跑。"""

    event = Signal(object)           # 携带 events.py 里的冻结事件对象

    def submit(self, cmd: Command) -> None:
        """线程安全投递命令到引擎事件循环。"""
        self._loop.call_soon_threadsafe(self._handle, cmd)


# 事件类型：TaskCreated / TaskProgress / TaskStatusChanged /
#          TaskLog / TaskFinished / TaskFailed / SniffFound
```

UI 侧只订阅 `engine.event`，按事件类型更新对应 model，绝不在 UI 线程做网络或磁盘重活。

### 4.4 HTTP 层（`core/http.py`）

- 全局单 `aiohttp.ClientSession`，`TCPConnector(limit=64, limit_per_host=8)`
- 重试：指数退避 `0.5 * 2^n + jitter`，最多 5 次；仅对 5xx / 429 / 连接异常；429 读 `Retry-After`
- 分层超时：连接 10s、读 30s、单分片总 120s；直播读超时独立配置
- 全任务可配 `User-Agent / Referer / Cookie / Origin`，嗅探加入下载时自动继承当前页面头
- 可选全局令牌桶限速（设置页 0 = 不限速）
- 进度按字节累加，1s 采样窗口算速度，ETA 用近 10s 加权滑动平均，避免抖动

### 4.5 分片下载与续传（HLS / DASH 共用）

任务目录布局：

```
%LOCALAPPDATA%/Muxer/tasks/{task_id}/
├── manifest.json      # 分片计划、已完成索引、配置快照
├── segments/
│   ├── 000001.ts
│   └── 000002.ts
├── video.mp4          # 中间产物
├── audio.m4a          # 中间产物
└── output.mp4         # 最终文件（合并成功后移动到用户目录）
```

- **原子写**：先写 `.part`，长度校验通过后 `os.replace()` 改名；异常中断不会留下半截分片被误认完成
- 恢复：读 `manifest.json`，跳过 `done` 集合，重试 `failed` 分片
- 失败策略：单分片重试 5 次仍失败 → 任务 `FAILED`，保留已完成分片，UI 提供"重试失败分片"
- 合并前检查磁盘剩余空间（`shutil.disk_usage`），不足直接提示

### 4.6 HLS（m3u8）

支持清单：

- `#EXT-X-STREAM-INF`（BANDWIDTH / RESOLUTION / CODECS / AUDIO 组）
- `#EXT-X-MEDIA`（独立音轨、字幕）
- `#EXTINF`、`#EXT-X-BYTERANGE`、`#EXT-X-MAP`（fMP4 init 段）
- `#EXT-X-KEY METHOD=AES-128`（URI / IV / KEYFORMAT）
- `#EXT-X-DISCONTINUITY`、`#EXT-X-ENDLIST`、`#EXT-X-MEDIA-SEQUENCE`、`#EXT-X-TARGETDURATION`
- 相对 URL 一律 `urljoin` 解析；key 请求沿用分片 headers

**加密**：AES-128-CBC，用 `cryptography`（已装 49.0）流式解密；IV 缺省时用分片序号 16 字节大端；`SAMPLE-AES` 检测到直接提示不支持。

**直播**：无 `ENDLIST` 判定为 live。轮询间隔取 `targetduration * 0.7`，按 `MEDIA-SEQUENCE` 增量抓取、去重；停止条件为手动 / 达到设定时长 / 出现 `ENDLIST`；全部下完后统一 concat。

**输出**：TS 分片 → `concat -c copy`；fMP4 分片 → init 段在前拼接；音轨独立时先 mux 再输出。

### 4.7 DASH（mpd）

- 解析 `Period → AdaptationSet → Representation`，按 `@codecs / @bandwidth / @width×@height` 生成变体列表
- 模板展开：`$RepresentationID$ / $Number$ / $Time$ / $Bandwidth$`，配合 `@startNumber / @duration / @timescale`
- `SegmentTimeline` 的 `S@t/@d/@r` 展开为时间轴；`SegmentBase + indexRange` 首版仅支持无 sidx 的简单场景
- 视频轨与音频轨分别取不同 Representation 下载，再 ffmpeg mux 成 MP4
- `ContentProtection`（DRM/Widevine/PlayReady）检测到即明确提示"加密流，不支持"，不做绕过

### 4.8 FLV

- 直接 HTTP GET 流式读取，边收边写 `.flv`，实时解析 tag 头（时长估算、音视频编码、关键帧）
- 结束条件：连接关闭 / 达到 `Content-Length` / 手动停止 / 空闲 30s 超时
- 直播 FLV 与点播 FLV 同一套逻辑，UI 显示"录制中"且进度条切换为不确定态 + 已录时长
- 完成后 `ffmpeg -c copy` remux 为 MP4（H.265 加 `-tag:v hvc1`）；H.264/AAC 通常秒转

### 4.9 ffmpeg 封装（`core/ffmpeg.py`）

| 功能 | 命令要点 |
|---|---|
| 探测 | `ffprobe -v quiet -print_format json -show_format -show_streams` |
| 拼接 TS | `-f concat -safe 0 -i list.txt -c copy -fflags +genpts` |
| 音视频 mux | `-i video.mp4 -i audio.m4a -c copy -map 0:v:0 -map 1:a:0` |
| 字幕 | MP4 用 `-c:s mov_text`，MKV 用 `-c:s copy` |
| 进度 | `-progress pipe:1 -nostats`，逐行读 `out_time_ms` |
| 取消 | Windows 下 `CREATE_NEW_PROCESS_GROUP` + `taskkill /T /F` 杀进程树 |

启动时检测 ffmpeg：先查 PATH，再查 `%LOCALAPPDATA%/Muxer/bin/`，都缺失则设置页引导手动选择路径。

## 5. 嗅探模块

QtWebEngine 的拦截器只给 URL，不给响应头，所以方案是"先粗筛、再探测"：

1. `QWebEngineUrlRequestInterceptor` 按扩展名与关键字粗筛（`m3u8 / mpd / flv / mp4 / m4s / ts` + 常见参数名）
2. 引擎侧异步探测：`HEAD`，失败回落 `GET Range: bytes=0-0`，拿 `Content-Type / Content-Length`
3. 命中 m3u8/mpd 的，直接下载文本解析出真实分辨率、码率、加密状态、时长，展示比裸 URL 友好得多
4. 去重：同 URL 只留一条；过滤已知心跳（同 URL 高频重复、1x1 封面、广告 CDN 黑名单规则）
5. 记录来源页面 URL 与 Cookie，作为下载默认 Referer/Cookie，解决防盗链
6. UI：页面底部抽屉列表，列（类型徽标 / 名称 / 大小或分辨率 / 操作），支持多选批量加入队列

**打包权衡**：QtWebEngine 会让安装包从约 70MB 涨到约 250MB。因此嗅探做成可选依赖 `PySide6-Addons`，未安装时隐藏嗅探页并给出提示，核心下载功能不受影响。

## 12. ffmpeg 分发策略对比

现有环境：`D:\ffmpeg-gpl-shared\bin`（GPL 动态版，ffmpeg + ffprobe + DLL 共约 158MB）。

| 维度 | A. 依赖系统 PATH | B. 内置 bin 打包 | C. 首启自动下载 |
|---|---|---|---|
| 安装包增量 | 0 | +100MB ～ +180MB | 0（下载后占本地约 100MB） |
| 用户门槛 | 需自行安装并配环境变量 | 开箱即用 | 开箱即用，但需联网一次 |
| 版本可控 | 低（用户环境各不相同） | 高（锁定已知可用版本） | 高（校验版本 + SHA256） |
| 离线可用 | 取决于用户 | 是 | 否 |
| 升级方式 | 用户自行升级 | 随应用版本发布 | 可独立更新 |
| 主要风险 | 用户未装 / 版本过旧 / 被其他软件抢占 | 包体大、GPL 分发义务 | 国内网络、镜像可用性、下载失败需兜底 |
| 适合场景 | 开发者自用 | 面向普通用户分发 | 追求小包体且可联网 |

分发方式的差异还会影响**许可证**：内置或代下 GPL 构建需随包提供对应源码或书面报价，并在关于页声明；本项目只做 `-c copy` 转封装、不重编码，因此选用 **LGPL 构建**即可满足功能，同时规避 GPL 传播义务。

**最终决策**：不实现首启自动下载。检测顺序为 `用户设置路径 > 内置 bin > PATH`，缺失时在设置页引导用户手动指定。开发期走 A（当前环境 `D:fmpeg-gpl-sharedin` 已就绪），M7 打包阶段切到 B（内置 LGPL 共享构建，规避 GPL 传播义务），设置页始终允许覆盖路径。

## 14. M2 实现记录（2026-11-26）

### 分层落点

```
UI 线程                     引擎线程 (asyncio)                   磁盘
──────                      ──────────────────                   ────
NewDownloadPage  ──probe──▶  Scheduler._probe ──▶ HttpClient
TasksPage        ◀─事件──   Scheduler / DirectSource  ──▶ Storage(SQLite)
MainWindow       ──命令──▶  EngineThread._pending  ──▶ tasks/<id>/payload.part
```

- 内核（`muxer/core/`、`muxer/protocols/`）不 import Qt，可脱离界面单测
- `EngineThread` 持有独立事件循环；UI 命令经 `loop.call_soon_threadsafe` 投递，引擎事件经 `Signal(object)` 跨线程排队回推
- 所有 UI ↔ 内核数据都是冻结的 `TaskSnapshot` / `ProbeResult`，避免跨线程共享可变对象

### 状态机实现

- `QUEUED → DOWNLOADING → COMPLETED`
- 暂停：排队中直接转 `PAUSED`；下载中置标记，源在下一个 64KB 分块边界抛出 `DownloadPaused`，保留 `.part`
- 续传：`PAUSED / FAILED → QUEUED`，用 `Range: bytes=<已有长度>-` 继续；服务器忽略 Range 时自动重头下载
- 取消：下载中置标记，等在途分块结束；随后删除记录、临时目录，发出 `TaskRemoved`
- 重启恢复：数据库里 `QUEUED / DOWNLOADING / POSTPROCESSING` 一律改为 `PAUSED` 并标注"上次退出时任务未完成"
- 归档：`清除已完成` 把 completed 记录标记 `archived=1`，任务页移除、历史页保留

### 关键参数

| 项 | 取值 |
|---|---|
| 分块 | 64 KB |
| 重试 | 最多 5 次，0.5 × 2^n 退避，封顶 20s，429 读 Retry-After |
| 超时 | 连接 10s，读 30s |
| 进度推送 | 每 200ms 一次；每 5s 落库一次 |
| 限速 | 全局令牌桶，设置页修改即时生效 |
| 并发 | 任务数来自设置（重启生效）；M2 每个任务单连接 |

## 15. M3 实现记录（2026-11-26）

### 新增模块

| 文件 | 职责 |
|---|---|
| `protocols/hls/playlist.py` | master / media 列表解析：STREAM-INF、MEDIA、EXTINF、BYTERANGE、MAP、KEY、DISCONTINUITY、MEDIA-SEQUENCE、ENDLIST |
| `protocols/hls/analyzer.py` | 拉取并分析播放列表：变体、时长、加密、直播、音轨；支持首选变体 |
| `protocols/hls/crypto.py` | AES-128-CBC 解密 + PKCS7 去填充 + 序号推导 IV |
| `protocols/hls/source.py` | 并发分片下载、断点续传、音轨分轨、ffmpeg 合并 |
| `core/ffmpeg.py` | ffmpeg / ffprobe 定位，concat / mux / remux，`-progress` 解析，失败带 stderr 尾部 |

### 下载流程

1. `analyze()`：拉取 m3u8，判定主 / 媒体列表；主列表按用户选择的变体或最高码率取媒体列表；解析备用音轨
2. 分片计划：按 `EXT-X-MAP` 判定 fMP4，按 `EXT-X-KEY` 获取解密参数；`BYTERANGE` 走 Range 请求
3. 并发下载：`segment_concurrency` 个工作协程，每个分片先写 `.part` 再原子改名；已存在文件直接跳过（续传）
4. 解密：AES-128-CBC；IV 取 EXT-X-KEY，缺省用分片序号大端 16 字节；密钥按 URI 缓存
5. 进度：以"分片数"为主进度，字节数用于速度 / ETA；`TaskRecord` 新增 `segments_done / segments_total` 并持久化
6. 合并：TS 走 ffmpeg concat，fMP4 走 init + 分片二进制拼接；有独立音轨时先各自成轨再 `-c copy` mux；状态先切 `POSTPROCESSING`
7. 落盘：合并文件移动到目标目录，按 `(1)`、`(2)` 避免覆盖

### 界面变化

- 探测结果展示时长、预估大小、Content-Type；HLS 主列表出现"清晰度"下拉（自动 / 1080P / 720P / …）
- 任务卡显示"分片 48/120"，合并阶段状态胶囊显示"合并中"
- 任务进度优先按分片比例计算；速度与 ETA 仍按字节滑动窗口
- 设置页的分片并发数与 ffmpeg 路径在下次启动时生效（已加提示）

## 16. M4 实现记录（2026-11-26）

### 新增模块

| 文件 | 职责 |
|---|---|
| `protocols/dash/manifest.py` | MPD XML 解析、BaseURL / 模板继承、SegmentTemplate / Timeline / SegmentList 展开、计划生成 |

| `protocols/dash/source.py` | 分片并发下载、断点跳过、fMP4 拼接 / TS concat、音视频合流 |
| `protocols/naming.py` | 从 HLS 抽出的标题 / 变体标签共用逻辑 |

### 解析范围

- `Period` 取第一个；记录 `mediaPresentationDuration` 与 `Period@duration`
- 模板属性按 `MPD → Period → AdaptationSet → Representation` 逐层覆盖（`media / initialization / duration / timescale / startNumber / timeline`）
- `SegmentTemplate`：
  - `$RepresentationID$ / $Number%05d$ / $Time$ / $Bandwidth$`
  - `SegmentTimeline` 的 `S@t/@d/@r`，支持 `r=-1` 按下一段起点或周期时长展开
  - 无 Timeline 时用 `@duration / @timescale` 与周期时长算分片数
- `SegmentList`：`Initialization@sourceURL` + `SegmentURL@media`
- 单文件回退：Representation 自带 `BaseURL` 且无模板时，把整个文件作为唯一分片
- BaseURL 逐层 `urljoin`；模板 URL 相对最近的 BaseURL 解析

### 下载与合并

1. 选择视频表示（界面指定 id 或最高码率）与音频表示（最高码率）
2. 分别下载 init 段与媒体分片，`seg_concurrency` 并发，`.part` 原子写，已存在分片跳过
3. 进度按分片数汇总（视频 + 音频），字节数用于速度
4. fMP4：init + 分片二进制拼接；TS / 其他：ffmpeg concat
5. 有独立音轨时 `-c copy` 合流；容器不是 mp4 时再 remux
6. 合并前推送 `POSTPROCESSING` 状态

### 界面变化

- DASH 探测展示时长、预估大小、清晰度下拉（表示 id 作为不透明值回传）
- 说明文案区分 HLS / DASH / 直链
- 任务卡同样显示分片进度与"合并中"

### 测试

`python -m unittest discover -s tests -t .` —— 42 个用例全部通过（约 21 秒）。M4 新增：

| 用例 | 覆盖 |
|---|---|
| 模板展开 | `$Number%05d$`、`$Time$`、未知占位符报错、ISO 时长 |
| 固定时长模板 | 分片数、init / media URL、总时长 |
| SegmentTimeline | `r` 重复、`$Time$` 与序号映射 |
| `r=-1` | 展开到周期结束 |
| 继承 | 各层 BaseURL 与模板覆盖 |
| SegmentList | init + 媒体列表 |
| 单文件 BaseURL | 整文件回退 |
| DRM / 直播 | `ContentProtection`、`type="dynamic"` 识别 |
| DASH 端到端 | 双轨下载 → 合并，ffprobe 可见 video + audio，时长 6s |
| 固定时长端到端 | 无 Timeline 的 MPD 同样可下载 |

### M4 已知边界

### 录制行为

- **HLS 直播**
  - 探测阶段识别无 ENDLIST 后允许开始下载，提示"持续录制，点击停止按钮完成并合并"
  - 按 `target duration × 0.7`（最小 1 秒）轮询，按 `MEDIA-SEQUENCE` 去重，窗口滑走的分片不会重复下载

  - 出现 ENDLIST、用户停止、到达时长上限任一条件即进入合并

- **HTTP-FLV**

- **公共**
  - 停止命令只对下载中的任务生效，源在下一个分片 / 数据块边界退出并正常返回，调度器标记完成
  - 暂停保留已录数据，继续录制从当前直播位置接着写（中间缺口不补）
